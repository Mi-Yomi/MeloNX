# MeloNX v12.1: исправление раннего вылета v12

В предоставленном прогоне v12 (`397fa13f187d`) игра завершилась примерно на
27-й секунде. Первая ошибка — `VK_ERROR_FEATURE_NOT_PRESENT` при
`vkCreateBuffer` с `HOST_ALLOCATION`; затем завершился поток рендера.
Процесс занимал около 3826 МиБ, ему оставалось доступно около 2318 МиБ.
Этот конкретный вылет вызван совместимостью пересобранного MoltenVK,
а не исчерпанием памяти. Изменение масштаба рендера эту ошибку не устраняет.

## Исправления

- В MoltenVK 1.4.0 перенесено upstream-исправление
  [c33ebc7e](https://github.com/KhronosGroup/MoltenVK/commit/c33ebc7e1ea491529477c795479ab414b335ab57):
  проверка external-memory create info теперь принимает поддерживаемый
  `HOST_ALLOCATION`. Сохраняются прежний autorelease backport и изменения
  времени жизни ресурсов из v12. Зависимости и оба патча закреплены хешами.
- Эмулятор проверяет именно создание импортируемого буфера. Прежняя проверка
  создавала обычный буфер и пропускала обнаруженную несовместимость.
  Если драйвер отвергает импорт, `TextureGroup` выбирает обычный буфер с
  копированием до начала чтения в гостевую память. Ошибки нехватки ресурсов
  и потери устройства не маскируются как отсутствие поддержки.
- Реестр импортов удаляет освобождённые выделения по сохранённому
  `DeviceMemory`. Ранее очистка значения в `Auto` лишала реестр идентификатора:
  оставались устаревшие записи, счётчики и возможность выбрать уже
  освобождённое выделение. Три теста воспроизводят дефект со старым сравнением.
- Ошибки создания и привязки импортируемого буфера освобождают подготовленное
  владение памятью; созданный native-буфер уничтожается до освобождения памяти.

## Проверки перед публикацией

Обязательная проверка на macOS собирает два драйвера из одних закреплённых
исходников: состояние v12 и вариант с исправлением host import. Каждый
загружается отдельным процессом. Контроль должен воспроизвести отказ создания
буфера; исправленный драйвер должен импортировать выровненную память,
привязать буфер с ненулевым смещением и пройти GPU-копирование в обе стороны
с ожиданием fence и сравнением байтов. Отсутствие Metal не считается успехом.
Это проверка нативного пути на macOS; выполнение iOS-драйвера на iPhone
проверяется отдельно на устройстве.

Сохраняется весь обязательный набор регрессий v12, добавлены тесты Vulkan
вызовов импорта, очистки реестра и обычного readback после отказа импорта.
CI публикует фактические TRX-результаты, native-отчёт, исходники, лицензии,
SHA-256 и соответствующие dSYM. Полнота тестов проверяется по именам.

## Проверка на iPhone

Установить IPA этой версии с прежними разрешениями памяти и активировать JIT.
Для сравнения оставить те же настройки и сохранение, на которых упала v12.
В начале лога должна появиться строка `Host-import buffer probe`; на
исправленном MoltenVK ожидаются `create=Success, enabled=True`.

Сначала проверить прежнее место раннего вылета в прологе, затем сцену
психолога и начало управления Франклином. Эти игровые переходы ещё не
подтверждены прогоном на устройстве. Исправление ранней регрессии само по
себе не доказывает устранение более позднего роста памяти. Для следующего
сравнения нужны новая сессия, memory.jsonl и core log; при закрытии процесса
системой полезен соответствующий JetsamEvent/`.ips`.
