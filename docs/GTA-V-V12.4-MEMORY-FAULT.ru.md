# MeloNX v12.4: обработка ошибок памяти и пустых страниц

Сборка исправляет ошибки в обработчиках памяти Darwin/ARM64 и убирает
ненужное заполнение пустых участков native page table. Основа — v12.3,
commit `1934106bd6686f13f9727ef4cb00e1f3ba487f88`.

## Что установлено по последней сессии

Завершение произошло с `Ryujinx.Memory.InvalidMemoryRegionException`
из `NativePageTable.VirtualMemoryEvent`: обращение попало в защитную страницу
таблицы гостевых адресов. Это зарегистрированное managed exception;
его нельзя классифицировать только как завершение iOS из-за нехватки RAM.

Непосредственно перед исключением footprint вырос примерно с 4916 до 5917 MiB.
Виртуальный размер процесса не изменился. Кто именно затронул дополнительные
страницы, старый журнал не показывает. GPU-очередь была пустой, вытеснений
buffer cache по лимиту/давлению не было, на отложенное уничтожение приходилось
лишь два native buffer общим логическим размером 32 байта. Поэтому механизм
вытеснения и пересоздания буферов из более ранних версий этот вылет не объясняет.

Последние этапы диагностики завершились; суммарная измеренная стоимость sampler
составила около 0,31% времени сессии. Это не доказывает полного отсутствия
влияния диагностики на тайминги, но её ограниченные буферы не объясняют
скачок примерно на 1 GiB. Пользовательские журналы не включены в репозиторий.

## Исправления

1. **Правильный `sigaction` на Darwin.** Раньше использовалась Linux-структура
   со 128-байтной маской и флагом `4`. Для Darwin теперь отдельная структура
   размером 16 байт, 32-битная маска и `SA_SIGINFO=0x40`. Linux-структура также
   получила естественное выравнивание поля `sa_restorer`.
   Основание: [публичный заголовок Apple XNU](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/signal.h).
2. **Раздельная передача SIGSEGV и SIGBUS.** Сохраняются оба прежних обработчика,
   их маски и флаги. Состояние передачи заполняется до установки обработчиков.
   При ошибке второй регистрации откатывается первая; восстановление пытается
   вернуть оба сигнала. `SIG_DFL` и `SIG_IGN` больше не вызываются как указатели
   функций: необрабатываемый синхронный fault возвращается стандартному
   механизму завершения. Некорректный доступ не превращается в успешное чтение.
3. **Сохранение контекста ARM64.** Если обработчик памяти вернул «не обработано»,
   адресный регистр остаётся прежним. При успешном перемещении сохраняется
   смещение адреса внутри инструкции. Флаг типа прежнего обработчика читается
   как 32-битное значение; чтение не захватывает соседнее поле.
4. **Ограниченный обход JIT breakpoint.** Прежний Swift-обработчик безусловно
   увеличивал PC и обнулял x0 при любом SIGBUS. Теперь это разрешено только
   для трёх конкретных точек BreakpointJIT: GetMapping, MarkMapping и Detach.
   Их машинные инструкции проверяются до установки обработчика. Все остальные
   сигналы передаются прежнему обработчику со своим контекстом. Если встроенный
   протокол не совпадает, dual mapping не запускается с неподготовленным fallback.
5. **Очистка native page table без лишней памяти.** `Unmap` пропускает участки,
   которые никогда не были committed. Раньше запись guard PTE в такие участки
   сама вызывала page fault и выделяла память для пустой таблицы. Живые соседние
   mappings сохраняются. Map/Unmap/Update проверяют границы и выравнивание до
   изменения таблицы, исключая переполнение размера и выход за адресное пространство.

Эти дефекты обнаружены в коде независимо от гипотезы о владельце скачка RAM.
Связь каждого из них с конкретной сценой GTA V пока не доказана. Исправления
не означают, что приложение сможет превысить установленный iOS лимит памяти.

## Что добавлено в отчёт

Для native page table записываются количество lazy read/write faults,
committed/reserved bytes и последнее обращение. Если защитная страница снова
будет затронута, исключение сохранит относительное смещение, направление доступа,
счётчики и **PC инструкции, вызвавшей native fault**. PC передаётся прямо из
контекста сигнала только callbacks, которые явно поддерживают этот аргумент;
остальные сохраняют прежний ABI. Инструкция по этому адресу в обработчике
диагностики не читается. PC — адрес native кода, а не автоматически восстановленный
гостевой адрес: разные недопустимые гостевые страницы используют общий guard.

Анализатор также исправлен: структурированный managed crash имеет приоритет
перед оценкой свободной памяти; поле `phase` в телеметрии больше не ломает CSV.
Поле телеметрии при конфликте экспортируется как `metric.phase`.

## Проверки перед выпуском

- Сохранены все обязательные регрессии v12.3 по графике, памяти, Python и Swift.
- Новые C# проверки выполняют настоящий сгенерированный signal handler на
  синтетическом Darwin/ARM64 контексте, не устанавливая системные обработчики.
  Проверяются сохранность регистров, разные сигналы, callback PC, успешная
  релокация и стандартные signal dispositions.
- Тесты native page table проверяют пустые участки с canary, соседние mappings,
  повторный unmap/remap, ошибочные диапазоны и счётчики guard/lazy faults.
- Отдельный macOS процесс сравнивает production `sigaction` с ABI реального
  Apple SDK, демонстрирует старый ошибочный флаг `0` и исправленный `64`,
  проверяет доставку и восстановление обоих сигналов. iOS arm64 SDK дополнительно
  проверяется компилятором.
- Swift/native проверка выполняет настоящие три ARM64 BRK, проверяет передачу
  посторонних сигналов и неизменность незнакомого контекста.
- GitHub Actions заново собирает MoltenVK из закреплённых исходников с теми же
  двумя backport и проверяет host import, затем собирает IPA и сохраняет symbols.
  Фактические результаты тестов приложены к релизу. Проверки на macOS не являются
  воспроизведением игровой сцены на iPhone.

## Проверка на iPhone

Установить IPA поверх приложения с сохранением данных, используя прежний способ
подписи. Полностью закрыть приложение и заново включить JIT. Для сравнения
оставить прежний профиль GTA V, гостевую память 4 GiB и JIT cache 512 MiB;
разрешение 0,5× достаточно для первого прогона. Не запускать RAM benchmark
одновременно с игрой. Пройти то же место из того же сохранения.

При повторном вылете сразу после открытия MeloNX экспортировать **Latest Memory
Diagnostics целиком** и прислать архив вместе с основным логом. Не запускать
несколько новых игровых сессий перед экспортом: предыдущие файлы ротируются.
Для разборa теперь особенно важны `fault_pc`, `table_committed_bytes` и
`lazy_write_faults` в тексте исключения. Отдельный системный IPS не требуется.
